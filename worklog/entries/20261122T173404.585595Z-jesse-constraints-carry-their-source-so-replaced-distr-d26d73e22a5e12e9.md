# constraints carry their source so replaced distributions' bounds are dropped

## Summary

While re-checking the first blocker I found my own bug: the constraints filter was keyed on
the requiring distribution but written as though it keyed on the constrained one, so which
bounds survived depended on an accident of dictionary contents rather than on the rule.

## Changes

- `pins.derive` records, per constraint line, both the constrained package and the
  distribution that imposed the bound.
- The artifact keeps a bound only when its requirer is *not* itself being replaced: a bound
  from the version being left behind must not constrain the version being installed.
- The rule is now stated where it is applied instead of being implied by a key choice.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 378 tests, OK.
- `tests/test_audit_fixes.py ConstraintSourceTests.test_a_bound_from_a_distribution_being_replaced_is_not_written`
  fails if the filter keys on the constrained package instead of the requirer.
