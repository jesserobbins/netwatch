# rework 9: labelled add identity, preview token writes, p0 and p11 cleanup

## Summary

The ninth audit found the CLI route I had certified could not work: `add` gives a target the
operator's label, while the identity read compared the *manager's* tool name against that label,
so only a target named exactly after the distribution could ever pass.

## Changes

- **Identity compares the recorded tool, not the label.** `add` stores `tool` (the manager's own
  name beside `name`, the operator's label) and `_identity` compares metadata against it, so
  `add mylabel uvtool --path …` checks and upgrades normally.
- **`add`'s duplicate check uses the blocking set**, which excludes `unresolved_path` *and*
  `identity_mismatch`: a mis-identified row must not block re-registering the same venv under the
  right name.
- **A failed token publication writes `not_bindable`** in preview's transaction, guarded by
  generation and `state_seq`, and records the reason — status no longer reports `live` for a venv
  that cannot be tokened.
- **(p0) decides a malformed probe before anything is written or resolved**, with the safe repair
  in the message, and **(p11) deletes the constraints file** on any refusal after it was written.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 413 tests, OK.
- Live, real uv 0.13.6: `add mylabel uvtool --path /tmp/lt/tools/rouge` then `check mylabel` →
  "2 installed packages | 0 available updates" (the label no longer breaks identity);
  `preview mylabel` on a read-only venv → "the target is not_bindable until one can be written"
  with state `not_bindable`; `preview` with a malformed probe → "Run incomplete: … delete …
  and re-run preview" and the constraints directory count unchanged (no artifact left).
