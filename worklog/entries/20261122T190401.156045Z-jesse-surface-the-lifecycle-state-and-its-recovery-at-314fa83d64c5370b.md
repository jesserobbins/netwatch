# surface the lifecycle state and its recovery at status

## Summary

The audit's point that `not_bindable` is invisible to the operator was only half fixed: the
recovery sentence went into the check report, but `status` shows the last saved report, which can
predate the diagnosis entirely.

## Changes

- `status` carries the target's lifecycle state, generation and removed flag from the columns.
- The display prints a `State:` line for any non-live target with the action that clears it —
  delete the probe and re-check for `not_bindable`, restore or remove for `unresolved_path`,
  inspect and re-register for `identity_mismatch` — and says plainly when a target is retired.
- The line is independent of the saved report, so the operator sees the state even when the last
  check predates it.

Live: `status ruff` on a `not_bindable` target prints
`State: not_bindable — no usable probe token: delete …/.netwatch-probe and re-run check (it is safe)`.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 408 tests, OK.
- Live at HEAD: the state line appears for `not_bindable` and is absent for `live`.
