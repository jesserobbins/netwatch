# suffix a taken target name instead of rebinding it

## Summary

Writing the usage manual surfaced a defect in registration: `store.add_target` treats an
existing name as a revival, so registering a scan row whose tool name matched a *live* target
silently rebound that target's body and path — the plan an operator approved could then
describe a different installation.

## Changes

- `scan.register` suffixes a name already used by a different live target (`ruff` → `ruff-2`,
  `ruff-3`, …), reports the name it used with a note, and leaves the existing target alone. A
  collision with a *removed* row still revives in place, which is what makes a retired name
  reusable.
- A name already used by a live target on the **same** venv is not a collision: the venv check
  refuses that earlier, with the message naming the target that tracks it.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 419 tests, OK.
- `tests/test_register.py RegisterNameCollisionTests` registers two different venvs whose
  receipts both name `ruff` and asserts the second lands as `ruff-2`, that the note says why,
  and that the two targets still point at their own realpaths.
