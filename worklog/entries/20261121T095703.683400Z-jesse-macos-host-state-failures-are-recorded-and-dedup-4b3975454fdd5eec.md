# macos: host-state failures are recorded and deduplicated

## Summary

When the post-scan reconciliation probe finds the host can no longer be
probed as the invoking user — or is no longer a macOS host — the refusal
is recorded as a `collection_failed` event before the check fails, so
`status` and `history` show what happened instead of silently keeping the
previous successful check as the last attempt. No further Homebrew
command runs against such a host. The root refusal and the row builder
are shared between the inventory and reconciliation readers, closing the
drift that twice produced bugs in exactly those copies.

## Changes

- netwatch/adapters.py: shared `brew_refuse_root` (root and macOS-host
  checks under a common `HOST_STATE_ERRORS` prefix) and
  `brew_formula_package` row builder used by both readers.
- netwatch/workflow.py: host-state errors from the reconciliation are
  recorded and re-raised; other reconciliation failures still degrade to
  a discarded scan.
- README.md: Homebrew's scanner is excluded from the one-hour cache.
- docs/DESIGN.md, docs/USAGE.md: precise completeness-gate wording; sudo
  requirement scoped to Linux OS updates.
- tests/test_app.py: refusal recorded, root-flip and per-keg removal
  regressions, and a successful apply carrying coverage into the plan
  result.
