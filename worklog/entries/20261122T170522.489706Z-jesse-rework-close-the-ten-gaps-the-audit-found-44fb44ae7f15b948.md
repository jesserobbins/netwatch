# rework: close the ten gaps the audit found

## Summary

The completion audit was rejected and it was right: check did not show available updates,
the launcher check was dead code, history was not generation-safe, expiry leaked its
constraints files, the structural check was a tautology, the classifier had no baseline,
approval binding was weaker than the spec, preview gated on `not_bindable`, pipx ignored
pip's own configuration, and `resolve` did not stale same-venv plans. This entry records the
rework of each.

## Changes

1. **`check` implements (c4)**: the outdated query runs (index options passed), a failure is
   recorded as `update_error` instead of an empty list, `uv pip check` entries become
   findings, and launcher results become findings plus warnings.
2. **Launcher verification is wired**, not dead code: `_launchers` runs from `check` against
   the manager's bin dir and the venv's own `bin/`, with a real verdict outranking
   "missing" from the other directory.
3. **Generation-safe history**: `Store.event` and `save_scan` stamp `generation`; `latest()`
   returns nothing for a report written before a remove/revive.
4. **Expiry and cleanup**: `expire()` deletes the staled plan's constraints file;
   `cleanup()` removes stale `apply-*.tmp`, unreferenced `preview-*.txt` older than an hour,
   and preview files of stale/resolved plans, with selection and unlink inside one
   `BEGIN IMMEDIATE`.
5. **The structural check is real**: it compares the live resolution against the realpath
   registration recorded, and registration now always records one (`scan.register` writes
   `realpath`). A target registered without one skips the test rather than faking it.
6. **The classifier has a pre-install RECORD baseline**: only damage the install introduced
   counts, so a venv that already disagreed with its RECORD still gets `failed_no_change`.
7. **Approval binding**: the inventory digest covers METADATA and `direct_url.json` bytes;
   the interpreter's `-I -S` marker values, the observed extras and the redacted index-option
   digest are recorded at preview and re-checked at apply; the claim transaction re-checks
   fingerprint, target row, path re-resolution, co-claimants and the probe; the apply temp
   copy is exclusive-create.
8. **Preview no longer gates on `not_bindable`** (recovering the token is what preview is
   for), and the index options are read *before* the outdated query and passed to it.
9. **pipx translates pip's own configuration**: `PIP_INDEX_URL`/`PIP_EXTRA_INDEX_URL`/
   `PIP_TRUSTED_HOST`, then pip.conf (via `PIP_CONFIG_FILE`, the user files, `/etc`), used
   when `pip_args` names no index — redacted like everything else, with `index_source`
   recording which one applied.
10. **`resolve` stales same-venv siblings** for the venv kinds, name-scoped as before for the
    rest.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 361 tests, OK (was 341; 20 new).
- New tests pin each finding: `tests/test_store_history.py` (generation on every writer,
  history not current after revival, expiry deleting its file, cleanup of temps and orphan
  previews), `test_venvflow.py` (`check` reporting updates, an update error, a broken
  launcher, path drift, preview recovering `not_bindable`, a pre-existing RECORD mismatch
  not blocking a retry), `test_register.py` (pip.conf and `PIP_*` translation, `pip_args`
  winning, redaction), `test_workflow_venv.py` (`resolve` staling a same-venv sibling and
  leaving an unrelated plan alone).
