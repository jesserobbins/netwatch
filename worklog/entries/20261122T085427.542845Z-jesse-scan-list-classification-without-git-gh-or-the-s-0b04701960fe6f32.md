# scan --list: classification without git, gh or the store

## Summary

A scan has to be safe to point at a root full of checkouts netwatch knows nothing
about. Reading a checkout can execute a configured clean filter, so the operator needs a
mode that classifies from directory structure alone and touches nothing else.

## Changes

- `netwatch/scan.py`: `walk` (depth, excludes, skip list, stop at repo root, no symlink
  following), `classify` (a venv is user-lane only when a manager receipt sits beside
  `pyvenv.cfg`), `summary`, `list_only`.
- `scan --list` is wired in the CLI **before** any `Store` is constructed, so the mode
  cannot create a database file or run the version migration. Plain `scan` refuses for
  now rather than exposing a half-featured walk.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 176 tests, OK (10 new).
- Live, on this machine:
  - `scan ~/GitHub --list --depth 3` → `103 repos, 0 user-lane, 1 unclassified`; the
    unclassified row is a bare `pyvenv.cfg` with no manager receipt, correctly refused.
  - `scan ~/.local/share/uv/tools --list --depth 2` → `0 repos, 5 user-lane` — the five
    real uv tool venvs on this host.
- `subprocess.run` and `Store` are asserted un-called by `test_list_runs_no_git_no_gh_and_opens_no_database`.
