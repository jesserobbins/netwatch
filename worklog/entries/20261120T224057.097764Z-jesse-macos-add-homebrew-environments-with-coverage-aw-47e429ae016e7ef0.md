# macos: add Homebrew environments with coverage-aware advisory reporting

## Summary

A macOS host can be registered as a `brew` environment and checked like the Linux
kinds: inventory, update discovery and a whole-environment upgrade, local or over
SSH. Vulnerability data comes from Homebrew's own OSV scan, with its coverage
limits reported instead of hidden.

## Changes

- `netwatch/adapters.py`: new `brew` kind; Darwin probe (`uname -s`, `uname -m`,
  `sw_vers`, `id -u`); `brew_env` carrying a fixed `PATH` and Homebrew's
  non-interactive settings inside the argv; formula and cask inventory from
  `brew list --versions`; update discovery from `brew outdated --json=v2` with
  and without `--greedy`, marking held and greedy-only entries.
- `netwatch/sources.py`: `brew_scan` reads `brew vulns --json`, tolerating exit 1
  only when the output parses; four outcomes (complete, partial, no scanner,
  malformed); findings keyed by formula, version and advisory. Cask names are
  excluded from pwn.watch tag matching.
- `netwatch/workflow.py`: coverage on the report; cask warning in the preview
  scope; inventory failures now carry the adapter's reason.
- `netwatch/store.py`: when coverage names the scanned set, a prior finding is
  cleared only for a scanned package and retained as `unknown` otherwise.
- `docs/USAGE.md`, `docs/DESIGN.md`: the `brew` rows, the coverage rules, the
  root refusal and the first-use registration example.

## Validation

`.venv/bin/python -m unittest discover -s tests` — 104 tests, OK.

Fixture strings came from this machine, not from memory: `brew list --versions`,
`brew list --cask --versions`, `brew outdated --json=v2`, and `brew vulns --json`
(15 findings over 175 checked formulae, `complete: false`, 61 skipped, one
untrusted tap). Homebrew here is 7.0.15.

Not verified: MacPorts (no `port` binary on this host, so no parser was written),
and a live `apply` against a real Homebrew, which needs an operator account and
an approved plan.
