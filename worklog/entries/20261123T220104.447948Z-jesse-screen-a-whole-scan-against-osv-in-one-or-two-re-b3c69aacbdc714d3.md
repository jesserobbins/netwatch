# screen a whole scan against OSV in one or two requests

## Summary

`scan.run` now asks OSV one batched question for the whole run instead of one per locked package. Every owned repo is read first (`tickets.inspect`), the locked packages are deduplicated per (ecosystem, name, version), the answers the hour cache already holds are skipped, and the remainder goes through one `sources.osv_batch` call; each repo's advisory pass then reads the screen answers from the cache and only the flagged packages get a detail query. The returned dict gains `advisory_requests: {"screen", "detail"}`, progress gains one `advisories: ...` line, and a refused or malformed screen leaves every affected repo's check incomplete instead of clean.

## Changes

- `netwatch/scan.py`: `run` restructured into phases — walk and classify (unchanged), `tickets.inspect` per owned repo, the deduplicated package union, `Store.cached_many` over the `osv-screen:` keys, one screen over the remainder with every answer cached under its key, then `tickets.advisories` per repo in walk order before the same ticket, event and record writes as before. `run` gains a keyword-only `screen=` (tests inject their own; the default wraps `sources.osv_batch` over the run's request, with a counting wrapper so `advisory_requests` reports the batch and detail requests actually made). `scan.report` is untouched.
- `tests/test_scan_run.py`: new `ScreenedRunTests` — the screen runs once per run over the deduplicated union, a second run inside the hour screens nothing, a failed screen leaves every affected repo incomplete, and progress gains exactly one `advisories:` line. `RunTests.test_a_repo_with_locked_packages_scans_with_the_cache` now answers the batch call and asserts `{"screen": 1, "detail": 1}`; the collection-yields-nothing test mocks `tickets.inspect`, the seam `run` now calls.
