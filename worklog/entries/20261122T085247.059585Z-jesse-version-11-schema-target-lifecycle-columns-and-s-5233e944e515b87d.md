# version-11 schema: target lifecycle columns and scan tables

## Summary

The scan feature needs per-target lifecycle state that plan staleness can read without
parsing the body JSON, plus a persisted scan so `--register` indexes into a stored record
instead of re-walking a tree that may have changed. Both land as schema version 11.

## Changes

- `Store` accepts version 0 (new), 10 (migrates) and 11 (current); version 12 and
  unversioned databases with tables are refused rather than stamped down.
- `_migrate_10_to_11` runs one `BEGIN IMMEDIATE`, re-checks the version under the write
  lock, ALTERs only absent columns, and backfills `kind` from the body JSON,
  `removed=0`, `state='live'`, `generation=1`, `state_seq=0`.
- `targets` gains `kind`, `state`, `removed`, `generation`, `state_seq`;
  `scan_runs`/`scan_records` are created for the scan feature.
- `add_target(kind, body)` and `remove_target(name)` are the writers: a removed name is
  reusable, revival resets the row into service, and both remove and revive bump the
  generation so plans approved before either event are refused as stale.
- Every writer (cli `add`, demo, three test seeds) now goes through `add_target` instead
  of a positional two-value INSERT the wider table rejects.
- Store connections raise `busy_timeout` to 60 seconds: the setting governs how long a
  *waiting* connection queues, and a registration batch holds the lock across listings.
