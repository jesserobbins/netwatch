# rework 6: launcher shadowing, not_bindable clear, p11, launcher dirs, addable kinds

## Summary

The sixth audit found the lifecycle half did not actually transition, and it was right: the
launcher loop reused the name `row`, so every state computation in `check`'s successful branch
ran against a launcher dict. It only stayed invisible because the executor's live runs had no
launchers, which is exactly the venv shape the ruff-only tests could not produce.

## Changes

- **The shadowing bug**: `for launcher in launcher_rows` — the target row is no longer
  overwritten, so `not_bindable`, `live` and `unresolved_path` all transition again.
- **Preview clears `not_bindable`** in the save transaction when the token on disk is still the
  usable one this run read, so the plan it writes is appliable.
- **(p11) no eligible update is an observation**, not an exception: preview reports
  `status: "no_update"` with the excluded candidates, clears `not_bindable`, and saves no plan.
- **Launchers naming the venv's own `bin/python`, which resolves to a shared base interpreter,
  are healthy** rather than leads — the exception the spec names.
- **pipx launchers are looked for where pipx exposes them** (`PIPX_BIN_DIR`, default
  `~/.local/bin`), falling back to the path the metadata names when it differs from the venv.
- **`add --kind uvtool|pipx` works**: the venv kinds are addable (`adapters.VENV_KINDS`) while
  `KINDS` stays the registry of kinds that speak the adapter protocol.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 398 tests, OK.
- Regression tests for the bug the audit found, each with a launcher present:
  a malformed probe sets `not_bindable`; a usable token lifts `not_bindable` to `live`; a
  returned venv recovers from `unresolved_path`; and preview clears `not_bindable` so the plan
  it saves is appliable (apply then reaches `applied`).
- Plus: the shared-base-interpreter launcher is `ok`; pipx's bin dir honours `PIPX_BIN_DIR`;
  `adapters.target(..., "uvtool")` is accepted and still requires a path.
