# separate reading a checkout from asking about its packages

## Summary

Split the repo lane's `collect` into `inspect(repo, *, runner)` (git and lockfile work only, returning the payload without advisory entries plus the locked packages) and `advisories(packages, *, request, cache, screen)` (one screen call over every package, then the existing single-query detail pass only where the screen flags). `collect` keeps its signature and output and now composes the two, gaining a keyword-only `screen=None`; with no screen every package is queried individually exactly as before.

## Changes

- `netwatch/tickets.py`: new `inspect` and `advisories` public functions; `collect` composes them; new `_screen` helper. The screen answer is cached per triple under `osv-screen:<ecosystem>:<name>:<version>` and the detail answer under the existing `osv-repo:` key, both for 3600 seconds; `cache` now follows the Store protocol (`cached_get`/`cached_put`). A screen that raises or replies short marks the check incomplete, never clean. uv packages now carry `direct: True` so every package dict has the five keys the advisory pass needs.
- `tests/test_tickets.py`: new `ScreenTests` — a clean tree issues no detail requests, a flagged package produces the same finding, a failed screen marks collection incomplete.

## Validation

TDD: wrote the three tests first, ran `.venv/bin/python -m unittest tests.test_tickets.ScreenTests -v` and watched all three fail with `TypeError: collect() got an unexpected keyword argument 'screen'` (RED). Implemented the split, re-ran the module (21 tests pass, GREEN — the 18 pre-existing ticket tests unchanged), then the whole suite `.venv/bin/python -m unittest discover -s tests -q` — 443 tests, OK. Also verified by hand that `inspect` returns no advisory entries, that a repeat advisory pass inside the hour makes no screen or detail calls, and that `screen=None` still queries every package.
