# split the advisory cache read from its write

## Summary

`Store.cached(key, loader)` does three things at once: check the cache, call the loader, and store
the result. Batched advisory queries need to ask about many keys before deciding what to fetch, and
to store many results afterwards, without a loader in between.

## Changes

- `Store.cached_get(key, max_age)` reads one entry or returns None; `max_age <= 0` means "do not
  use the cache", which is how `--refresh` still asks for a fresh fetch.
- `Store.cached_put(key, value)` writes one entry.
- `Store.cached(key, loader, ...)` is now those two around the loader, so every existing caller —
  the feeds in `check` — behaves exactly as before.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 432 tests, OK, including the refresh test
  that pins `max_age=0` fetching rather than reading.
