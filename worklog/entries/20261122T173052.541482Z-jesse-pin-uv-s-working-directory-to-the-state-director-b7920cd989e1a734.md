# pin uv's working directory to the state directory in the CLI

## Summary

The audit's sixth blocker had two halves and I had only fixed one: venvflow pinned its
runner to the state directory, but the CLI built its runner with a target that carried no
path, so uv still inherited the launch directory and a repo-local `[tool.uv]` could shape
resolution between preview and apply.

## Changes

- `cli.one_argv(runner, t, state_dir)` passes the state directory as the target path, which
  is what `adapters.run` uses as `cwd`.
- `cli.state_dir_for(args)` derives it from `--db`, the same directory the plan's constraints
  artifact is written to, so approval artifacts and uv's working directory agree.
- `check`, `preview` and `apply` all pass it; `preview` also passes `state_dir` so the
  fingerprint hashes the configuration files in that hierarchy.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 376 tests, OK.
- `tests/test_audit_fixes.py FingerprintEnvironmentTests.test_the_local_runner_pins_the_working_directory_to_the_state_dir`
  pins the venvflow half; the CLI half is exercised by the live end-to-end recorded in the
  previous entry, which ran with `--db /tmp/lt/v5.db`.
