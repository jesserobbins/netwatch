# docs: record the delivery and correct stale scope claims

## Summary

Three documents still described the product as it was before this branch, and one of them —
`docs/DELIVERY.md` — had no record of the work at all: the delivery checklist is what a reader
consults to learn what was built and how it was verified.

## Changes

- **`docs/DELIVERY.md`** gains a *Scan, repo tickets and tool venvs* section: the walk and its
  bounds, `--list` having no side effects, stored runs and index-based registration with the
  name-suffix rule, the four repo-lane findings and the ticket write policy, the two venues kinds
  and their launcher verification, the lifecycle machine and schema 11, probe-bound approvals,
  the ordered apply verifications and the `applied` conditions. It records the verification that
  was actually done — 419 tests, demo, packaging check, and the live throwaway-tool-home upgrades
  for both kinds with the probe refusal and lifecycle transitions — and states that OS
  package-manager updates were not run. The closing *Before using live updates* line no longer
  says nothing has been tested.
- **Stale claims corrected**: `README.md` and `docs/USAGE.md` said live updates had never been
  tested; tool-venv upgrades have been exercised end to end, OS ones have not, and both now say
  exactly that. The scope sentence that read "custom uv environment locations … are not scanned"
  now says a scan sees only what lies under the root it is given and does not consult uv's or
  pipx's own registry, which is what the code does.
- **`AGENTS.md`** describes netwatch as also scanning a root and writing tickets, and its reading
  pointer names scanning, repo tickets and the design contract's behavior section, with one
  sentence on `--list` being the safe first look and registration being a separate step.

  `git diff --check` — clean.
- Every claim added to the delivery record was checked against the tree or a live run first: the
  five-index batch cap, `--list` opening no database, the ticket refusal set, the token line
  format, the schema gate, and the constraints directory beside the database.
