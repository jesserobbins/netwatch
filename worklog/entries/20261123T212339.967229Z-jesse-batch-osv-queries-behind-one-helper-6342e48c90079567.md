# batch OSV queries behind one helper

## Summary

A repo-lane scan asks OSV one HTTP question per locked package; a real tree is ~1,200
sequential requests. `sources.osv_batch` asks `POST /v1/querybatch` instead, at most 1,000
queries per request, and returns advisory ids per query in input order with pagination
already resolved. Nothing consumes it yet; a later task screens a scan with it.

## Changes

- `sources.OSV_BATCH = "https://api.osv.dev/v1/querybatch"`, added to the URL allow-list in
  `fetch`, so batch calls pass the endpoint guard.
- `sources.user_agent()` returns `"netwatch/" + __version__` from `netwatch/__init__.py`;
  `fetch` now sends it instead of the hard-coded `"netwatch/0.2"`, so the identifier has one
  source of truth.
- `sources.osv_batch(queries, *, request=fetch, chunk=1000)` sends `{"queries": chunk}` per
  request, reads `results`, and collects `vulns[*].id` per query. A result carrying
  `next_page_token` re-asks only that query with its token appended and merges ids in place,
  until no token remains. A refused batch (`Error` from the request) halves `chunk` and
  re-asks the same queries until they fit; at `chunk == 1` the error propagates. A malformed
  reply raises `Error("OSV batch response is malformed")` and is not retried, because a
  smaller batch cannot fix a malformed response.
- `tests/test_osv_batch.py`: input order, the 1,000-query cap, refusal-retry with a smaller
  chunk, page-token follow-up, and two identification tests — one captures the `Request`
  object `fetch` builds for a batch call (patching `urllib.request.build_opener`) and asserts
  its `User-Agent` header starts with `netwatch/`, one asserts `user_agent()` names netwatch.
