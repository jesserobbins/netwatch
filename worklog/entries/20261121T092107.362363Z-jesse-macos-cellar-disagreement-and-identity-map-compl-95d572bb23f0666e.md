# macos: cellar disagreement and identity-map completion

## Summary

The Cellar listing runs after the `brew info --installed` read, so a
formula it no longer shows was removed in between: the inventory reader
now treats that disagreement as an error rather than combining two
observations of different host states. In the post-scan reconciliation
the same reader failure discards the scan, so a finding can no longer be
saved for a keg the final listing showed was gone.

## Changes

- netwatch/adapters.py: `brew_formula_rows` raises on a formula the
  metadata read knows but the Cellar listing does not.
- netwatch/sources.py: the partial-coverage warning compares retained
  identities against scanned identities and their short names; a formula
  both refused and stale forces the accounting to fail; an unmatched
  ambiguous-keg formula gets its own warning instead of a re-run advice.
- netwatch/cli.py: the updates view groups same-named rows per
  ecosystem.
- tests/test_app.py: regressions for each of the above.
