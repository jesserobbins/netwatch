# describe batched advisory screening in the docs

## Summary

The user-facing docs still described the pre-batching behaviour: `docs/USAGE.md` said a scan pays "one OSV advisory query per locked package". Tasks 1-4 replaced that with a batched screen, so the scan section now describes the screen-then-detail flow, the hour cache on both layers, the honest cold and warm timings, the `netwatch/<version>` identification, and the incomplete-on-failure rule. `docs/DESIGN.md` gains one bullet under *Behavior to preserve* so the batching, sequencing, pagination, identification, cache key and incomplete-on-failure semantics are pinned as behaviour a future change cannot silently drop.

## Changes

- `docs/USAGE.md` (scan section): replaced the sentence "The slow part is the checkout reads — git queries plus one OSV advisory query per locked package — so a first scan of a large root takes minutes while a repeat within the hour is near-instant from the advisory cache." with: the slow part is the checkout reads; netwatch screens every locked package against OSV in batched requests of up to 1000 packages and asks for per-package detail only where the screen finds an advisory; a failed screen makes the affected packages an incomplete advisory check, never a clean one; both layers are cached per `(ecosystem, name, version)` for an hour, so a repeat scan inside the hour makes no advisory requests; on a tree of roughly 1,700 locked packages the screen and the detail queries took 27.2 s on a first scan and 2.0 s on a repeat, down from about 1,200 single-package requests over two and a half minutes; OSV publishes no rate limit and netwatch stays sequential, sending every request as `netwatch/<version>`.
- `docs/DESIGN.md` (*Behavior to preserve*): new bullet after the retained-findings one - "Advisory screening is batched and strictly sequential: the screen asks `querybatch` in pages of up to 1000 packages, paginates refusals and continuation tokens, identifies itself as `netwatch/<version>`, and caches per `(ecosystem, name, version)` for the hour; a failed screen is an incomplete check, never a clean one."
- No code, test, README or `docs/DELIVERY.md` change.
