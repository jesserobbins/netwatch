# Two documentation defects found by the final review of the host-guide pass

## Summary

The host-guide pass shipped two documentation defects that the final read caught. The README's Mac walkthrough ran `--register` without a stored scan between it and `--list`, and the new guide dropped a coverage fact the manual it replaced had stated: a casks gets no pwn.watch lead.

## Changes

- `README.md`: the plain `scan` now sits between `--list` and `--register`, with one line saying registration needs a stored run.
- `docs/MACOS.md`: the cask paragraph names pwn.watch matching and the reason casks stay out of it, which is that a cask name can collide with an unrelated project.

## Validation

- Reproduced the first defect against a synthetic root before fixing: `scan --list` then `scan --register 1` returns `{"error": "no scan of <root>; run scan first"}`. After the fix the same sequence stores a run (`scan run 1: 0 repos, 1 user-lane, 1 unclassified`) and registration accepts the row.
- Reproduced the second with `grep pwn.watch docs/MACOS.md` before the fix, and read the reason back from `sources.pwn_context`, which skips `Homebrew-cask` packages.
- Links and anchors resolve, every fenced bash block parses, no private path in tracked files, `.venv/bin/python -m unittest discover -s tests -q` → Ran 449 tests, OK.
