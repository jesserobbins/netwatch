# macos: unloadable kegs, single metadata load, and trim corrections

## Summary

An online Homebrew check now runs `brew info --installed --json=v2` once
for the inventory and once for the post-scan reconciliation, instead of
three times: the considered set and the full-name map are derived from
the inventory the check already collected, so the scan's accounting no
longer needs its own metadata load.

An untapped tap's keg keeps its finding. Verified against Homebrew's
source (`Formula.installed` skips racks whose formula cannot load;
`brew list` reads the racks), the inventory cross-checks both commands
and marks kegs known only to the list `unloadable`: installed, never
credited clean, retention pairs carry an `unloadable` marker that the
store and the context carry-forward match by short package name, because
the tap-qualified identity the earlier finding recorded no longer
exists.

## Changes

- netwatch/adapters.py: `brew_formula_rows` yields an `unloadable` flag
  from the Cellar cross-check.
- netwatch/sources.py: considered set and full-name map derived from the
  collected inventory; unresolvable stale targets force the accounting
  to fail; unloadable retention pairs are marked; offline and no-scanner
  retention pairs carry the inventory's tap identity.
- netwatch/store.py: unloadable pairs match prior findings by short
  name; a trimmed fresh row's retained copy is restored in incomplete
  sources; retained rows keep their original matched references.
- netwatch/workflow.py: reconciliation compares the unloadable flag;
  carry-forward matches unloadable pairs by short name.
- netwatch/cli.py: the greedy-only marker reads "[not in default upgrade
  as observed]" because a cask can become outdated between the two
  queries.
- tests/test_app.py: untap regression (tap-qualified finding stays
  unknown), stale-shadow regression, unloadable regression, offline
  retention assertions.
