# read many advisory cache entries in one query

## Summary

Added `Store.cached_many(keys, *, max_age=3600)` beside `cached_get`/`cached_put` so a whole scan's advisory cache keys are read in chunked `SELECT ... WHERE key IN (...)` statements (500 keys per statement) instead of one query per key. Only present and fresh entries are returned; absent or stale keys are simply missing, and `max_age <= 0` means "do not use the cache" (returns `{}`), matching `cached_get`.

## Changes

- `netwatch/store.py`: new `cached_many` method (no change to `cached_get`, `cached_put`, or `cached`).
- `tests/test_store_cache.py`: new tests — fresh hits only (`max_age=0` returns `{}`) and a 1,200-key list that would otherwise exceed SQLite's bound-parameter limit.

## Validation

TDD: wrote the two tests first, ran `.venv/bin/python -m unittest tests.test_store_cache -v` and watched both fail with `AttributeError: 'Store' object has no attribute 'cached_many'` (RED). Implemented `cached_many`, re-ran the module (both pass, GREEN), then the whole suite `.venv/bin/python -m unittest discover -s tests -q` — 440 tests, OK.
