# macos: scan rows matched by tap-qualified identity

## Summary

Scan rows are now matched against installed kegs by the tap-qualified
name Homebrew reports (`full_name`) against the tap-qualified keg
identity from `brew info --installed --json=v2`. A core scan row for a
name the inventory knows only under a tap contradicts the accounting
(`unaccounted`) instead of publishing an advisory about — or clearing a
prior advisory for — the wrong keg. The considered-set comparison uses
the same identities, and a stale target (`outdated_without_sbom`) whose
identity is not an installed formula can no longer lend its checked slot
to another keg.

Validation hardening in the same round: both installed-formula readers
reject a non-list `formulae` (an empty-shaped response could otherwise
retire prior findings); retention metadata in a reconciliation-rejected
report describes the saved pre-scan inventory; a failing verification
step after the approved commands no longer blames the last approved
command; surviving context rows recompute `matched_references` against
the final findings, including in incomplete sources (retained history
still stays); and `strip_credentials` keeps IPv6 hosts bracketed.

## Changes

- netwatch/sources.py: identity-keyed keg index and row matching; stale
  identity outside the inventory forces the accounting to fail; both
  installed-formula readers require a list; single full-name inversion;
  bracketed IPv6 hosts survive credential stripping.
- netwatch/workflow.py: retention metadata of a rejected report describes
  the saved pre-scan inventory; `last_argv` cleared after the approved
  command loop.
- netwatch/store.py: fresh context rows trimmed in incomplete sources
  with `matched_references` recomputed; retained history stays.
- netwatch/cli.py: the cask marker keys on any installed formula of the
  same name.
- tests/test_app.py: stale-outside, core-row, IPv6 and trim regressions.
