# pinned constraint derivation, origin rules, launcher checks, verified install argv

## Summary

An upgrade has to hold the environment's own declared bounds, keep the extras the tool
actually needs, and never mistake a direct-origin install for an index one. This task is the
policies those decisions rest on — plus the one install argv, verified against the uv on this
machine before anything is built on it.

## Changes

- `netwatch/pins.py`:
  - `derive` — the fixed-point procedure: bounds are read from every installed
    distribution's `Requires-Dist` except the ones being replaced; a candidate that
    violates a bound in force is blocked *for that pass*; each pass retires the selections'
    old bounds and re-selects; the loop stops when the selection stops growing, bounded by
    installed count + 1.
  - Extras — the tool's own pin carries its observed extras, an upgraded dependency keeps
    extras from retained requirements whose marker is absent or true, and a reference
    guarded by an extra nobody knows about becomes a lead rather than a guess.
  - `origin` — PEP 610: missing file is index origin, unreadable is an incomplete
    observation, malformed or provenance-less is **undetermined** (which makes a target
    unplannable), otherwise vcs/local/direct.
  - `entry_points` / `launchers` — expected scripts come from the *registered*
    distribution's own `entry_points.txt`; each wrapper is checked for existence, for the
    entry point it invokes, and for an interpreter inside the venv under both recorded
    spellings, with the `#!/bin/sh` trampoline's interpreter read from its `exec` line
    instead of the shebang. Written-inside-but-resolves-outside is a raw lead, not a
    failure.
  - `command` / `redacted` / `plan_body` — `uv pip install --python <realpath>/bin/python
    -c <constraints> <recorded index options> <pins>`, no `--upgrade`, no `--no-config`;
    credentials stripped for display and comparison.
- `packaging==25.0` added to `pyproject.toml`; `uv lock` and `uv export` regenerated
  `requirements.lock`.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 300 tests, OK (27 new:
  `tests/test_pins.py` 17, `tests/test_launchers.py` 10).
- **The install argv, run against the real uv (0.13.6)** in a throwaway venv:

  ```
  argv: ['uv', 'pip', 'install', '--python', '…/v/bin/python', '-c', '…/constraints.txt',
         'packaging==25.0']
  has --no-config: False | has --upgrade: False
  exit: 0
  stderr: Installed 1 package in 1ms / + packaging==25.0
  installed: packaging-25.0.dist-info
  ```

  So the shape is accepted by the runtime, not just by a fixture.
- `requirements.lock` carries `packaging==25.0` with hashes.
