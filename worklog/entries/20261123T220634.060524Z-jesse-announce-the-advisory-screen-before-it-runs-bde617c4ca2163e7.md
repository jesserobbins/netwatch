# announce the advisory screen before it runs

## Summary

A scan's only slow phase could read as a hang: between the per-item lines and the `advisories:` outcome line the run sits silent while the OSV batch is in flight. The screen is now announced before it runs — `advisories: screening <N> packages (<C> already cached)`, through the same progress channel — so the wait is named, and a warm run shows the cache holding most of the work. A fully cached scan prints no announcement; the outcome line and everything else are unchanged.

## Changes

- `netwatch/scan.py`: one `say(...)` inside the existing `if missing:` block, immediately before the `run_screen(...)` call; no other line moved.
- `tests/test_scan_run.py`: `test_progress_gains_exactly_one_advisories_line` became `test_progress_announces_the_screening_before_the_screen_runs` — the screen stub appends a marker into the progress channel, so the test pins the announcement before the screen call and the outcome line after it. New `test_a_fully_cached_scan_announces_nothing_to_screen` pins that a warm run keeps only the outcome line.
