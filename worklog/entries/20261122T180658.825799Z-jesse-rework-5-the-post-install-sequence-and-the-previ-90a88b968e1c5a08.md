# rework 5: the post-install sequence and the preview bracket reads

## Summary

The fifth audit found the post-upgrade verification was a sketch: an unreadable `uv pip check`
still reported `applied`, there was no second token read, and no identity read ran after the
install — so a venv that stopped being this tool, or was replaced, could be reported as a
successful upgrade. It also named three smaller deviations.

## Changes

- **The post-install sequence follows the spec's order**: probe read, identity and inventory,
  the consistency check, then the probe again. Identity is read *after* the inventory and
  consistency check, so a venv that stopped being this tool during those reads is caught.
- **An unreadable consistency report satisfies no condition**: the gate tests
  `after_consistency is None` explicitly instead of folding `None` into an empty set.
- **A probe that changes during the post-install observation fails the gate**, compared
  across the two reads and against the pre-install token.
- **An expired plan is transitioned, not merely refused**: it moves to `stale` and its
  constraints file is deleted, so a refusal leaves nothing applicable-looking behind.
- **A held distribution that disappeared fails the gate**: a direct/VCS/local pin that the
  resolution removed is `needs_attention`, not an exemption.
- **Preview's bracket does its own reads**: (p7) a listing inside the bracket (a mismatch
  against the identity listing saves nothing) and (p9) a third fingerprint sample.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 390 tests, OK.
- `tests/test_audit_fixes.py PostInstallSequenceTests` (4 tests, each failing without its fix):
  an unreadable post-install `uv pip check` -> `needs_attention`; a probe that changes during
  the post-install observation -> `needs_attention`; a venv that stops being this tool after
  the install -> `needs_attention`; an expired plan -> `stale` with its artifact removed.
