# rework 4: bracket digest, preview re-reads, claim cleanup, artifact re-read

## Summary

The fourth audit found that the ordered sequences were only imitated: the apply digest came
from the wrong listing, preview tokened before re-confirming identity and never confirmed
again before saving, a refused claim left its verified copy behind, and the save
transaction never re-read the artifact the plan names.

## Changes

- **Apply's digest is taken inside (3)**: the bracket opens with the token read, then runs
  its **own** listing and computes the digest from that, then reads the token again. The
  step-(2) listing is no longer reused as the digest observation.
- **Preview re-confirms identity twice**: once immediately after publication (a venv that
  took the path before tokening is refused) and once before the plan is saved.
- **A refused claim deletes the verified copy**: the claim transaction is wrapped so any
  refusal unlinks the `apply-*.tmp` written by step (5), not only the install path's
  `finally`.
- **The save transaction re-reads the artifact**: presence and digest are checked inside the
  transaction that writes the plan, so a preview whose constraints file was swept saves
  nothing.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 386 tests, OK.
- `tests/test_audit_fixes.py BracketSequenceTests` (4 tests, each failing without its fix):
  - a version change after the identity listing is caught inside the bracket (the runner
    answers successive listings differently);
  - preview refuses when identity fails on the post-publication re-read;
  - a claim refused by a moved target leaves no `apply-*.tmp` behind;
  - a swept constraints file saves no plan.
