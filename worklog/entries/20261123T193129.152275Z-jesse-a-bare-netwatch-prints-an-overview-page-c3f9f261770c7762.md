# a bare netwatch prints an overview page

## Summary

Running `netwatch` with no arguments produced an argparse error and exit 2. The first thing a new
user or agent does is exactly that, and the answer it got was a usage line listing subcommands
with no order, no model and no examples.

## Changes

- The subcommand is no longer required, and a bare invocation prints an overview: the five-step
  loop (scan `--list` → register → check → preview → apply), commands grouped by what the operator
  is trying to do, the supported kinds, where state lives, and where the manual is.
- It is printed **before any `Store` is opened**, so asking for help can never create or migrate a
  database; a test asserts the file does not appear.
- Styling follows the rest of the CLI: bold cyan on a colour terminal, plain text otherwise, and
  `NO_COLOR`/`TERM=dumb` respected. Help stays text even under `--json`, because help is not data.
- `--help` and per-command help are unchanged.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 427 tests, OK.
- `tests/test_cli_overview.py`: exit 0 and the expected content; every command the parser accepts is
  named in the page; `--db` points at a path that must not be created; `--json` still prints the
  page; and `parse_args([])` yields no command rather than raising.
- Ran it live: `python3 -m netwatch` prints the page and exits 0; `netwatch --help` and
  `netwatch scan --help` still show argparse's own output.
