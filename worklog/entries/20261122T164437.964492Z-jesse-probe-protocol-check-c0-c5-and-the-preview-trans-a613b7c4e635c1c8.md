# probe protocol, check (c0)-(c5) and the preview transaction

## Summary

The observation half of the venv kinds: one provenance token per venv, the check sequence
that decides what a target's state is, and a preview that saves an approval only when the
environment held still long enough to describe it.

## Changes

- `netwatch/probe.py`: `read` (usable / absent / malformed / unreadable), `publish` (temp
  file then `os.link`; `EEXIST` means another run won and its token is the one to use),
  `cleanup` (strict name pattern plus one hour — content is never the test, because a
  crash leaves truncated content), and `witness` (the token, or inode numbers only when no
  token was readable at either read).
- `netwatch/venvflow.py`: `check` implements `(c0)`–`(c5)` in order — stored state and
  co-claimants, structural read with the path re-resolved, token read, runtime identity,
  publication and temp cleanup only after a passing identity read, the identity re-read,
  inventory plus OSV, then the closing witness plus a redist presence re-check. A
  mismatched witness or a vanished distribution publishes no findings. State writes are a
  compare-and-set on `generation` and `state_seq`, so a stale observation writes nothing
  and records itself `superseded`.
- `previous_event` feeds the two-in-a-row rules, so an absence needs the *previous* check
  observation to pair with, not the target body.
- `preview` implements `(p-1)`–`(p11)`: out-of-service refusal, identity gates, publication,
  a single recorded index-options read, three fingerprint samples that must agree,
  candidate selection via `uv pip list --outdated`, `pins.derive`, a per-plan constraints
  file whose path and digest go into the plan, and a save transaction that re-reads the
  target row and the token.
- A target with a co-claimant publishes nothing at all — it records the observation and
  refuses, which is what keeps one venv from being reported under two names.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 329 tests, OK (29 new:
  `tests/test_probe.py` 14, `tests/test_venvflow.py` 15).
- Contract items: publication race (a loser adopts the winner's token and leaves no temp),
  the closing-witness rule (a token readable at one read and absent at the other is a
  mismatch, never an inode fallback), the stored-state gate (a co-claimed venv publishes
  nothing), and the fingerprint bracket (a change between samples saves no plan).
- **Live, against a throwaway uv tool venv** (`UV_TOOL_DIR=/tmp/lt/tools`, ruff pinned back
  to 0.8.0 so an upgrade exists):
