# rework 10: one launcher pass, the as-written root, and what identity names

## Summary

The tenth audit found launcher verification producing wrong output on this machine's own path
conventions: every launcher was verified once per exposed script, and the as-written spelling the
spec relies on was erased before it could ever be compared.

## Changes

- **One verification pass.** `_launchers` runs `pins.launchers` once and maps the results onto the
  manager's exposed list; looping it verified the whole set once per script (25 rows for 5
  scripts on a real pylint venv).
- **The as-written root survives the scan.** `scan.run` walks the operator's spelling and keeps
  the resolved path only as the run's identity, so a launcher that names `/tmp/...` inside a
  `/private/tmp/...` venv is recognised as inside; `pins.launchers` takes that second root.
- **An identity failure names the metadata's tool** in the refusal and the event, not just the
  path.
- **A dedicated test** pins that apply refuses a stored `not_bindable` plan.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 415 tests, OK.
- Live, a script-launcher tool (pylint, installed with uv into /tmp/lt and scanned through the
  `/tmp` spelling): `_launchers` returns 4 rows for 4 scripts — pylint, pylint-config, pyreverse,
  symilar — all `ok`, and `check pylint` prints no launcher warning. Before: 20+ duplicated rows
  and five spurious "interpreter … is outside …" lines per script.
- Tests: LabelledAddTests, ApplyNotBindableTests, IdentityReportTests plus the earlier suite.
