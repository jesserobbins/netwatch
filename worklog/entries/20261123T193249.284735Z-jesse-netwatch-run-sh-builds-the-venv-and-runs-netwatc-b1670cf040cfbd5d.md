# netwatch-run.sh builds the venv and runs netwatch

## Summary

From a checkout there were five manual steps before netwatch would run — create the venv, activate
it, install the hash-pinned requirements, install the package, then remember you were inside a
shell that had done all that. Building a second shell or returning the next day meant repeating it
or discovering the venv had drifted from `requirements.lock`.

## Changes

- `netwatch-run.sh` at the repository root builds `.venv` with a Python 3.12+ interpreter, installs
  `requirements.lock` with `--require-hashes` and the package in editable mode, then `exec`s
  netwatch with the arguments it was given, so exit status and signals pass through unchanged.
- It installs once. A stamp inside the environment records a digest of `pyproject.toml` and
  `requirements.lock`; a run whose digest matches goes straight to netwatch (measured at 0.27 s
  here), and `NETWATCH_SETUP=always` forces the install.
- It prefers `uv` when present and falls back to `pip`; installer output goes to
  `.venv/.netwatch-setup.log` and only its tail is shown on failure, so a normal run is quiet.
- Notes go to **stderr**, so `--json` output is untouched on stdout, and the script works from any
  working directory because it resolves its own location.
- `NETWATCH_VENV` and `NETWATCH_PYTHON` choose where to build and with which interpreter;
  `NETWATCH_QUIET=0` shows the installer at work.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 427 tests, OK.
- `tests/test_runner_script.py` guards the script: it exists, is executable, passes `bash -n`, and
  refuses a missing interpreter with exit 127 and a message naming `NETWATCH_PYTHON`.
- `shellcheck netwatch-run.sh` — clean.
- Run by hand: a fresh `NETWATCH_VENV=/tmp/nw-run-test ./netwatch-run.sh` created the venv,
  installed, and printed the overview (exit 0); the second run printed nothing and took 0.27 s;
  `--json list` from `/tmp` returned only JSON; `scan /tmp/lt/tools --list` worked from outside the
  repository; `NETWATCH_SETUP=always` reinstalled; and the default path ran against the existing
  checkout `.venv`.
