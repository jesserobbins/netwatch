# apply, post-install gate, failed-install classifier and CLI activation

## Summary

The mutation half: apply runs the one approved argv, then decides what actually happened —
applied, needs_attention, or failed_no_change — and the venv kinds become reachable from the
CLI.

## Changes

- `venvflow.apply` implements steps (0)–(5) in order — workflow gates (status, busy plan on
  the same venv, generation, stored state, expiry, fingerprint), recorded path, runtime
  identity plus a co-claimant refusal, the binding bracket (probe token, inventory digest,
  a second token read), the constraints digest, and a verified temp copy — then claims in
  one transaction that re-reads the target row under the write lock.
- The five-condition `applied` gate: exit 0 **and** the probe token unchanged **and** the
  approved pins actually installed **and** no new `uv pip check` entry against the plan's
  baseline **and** no distribution's origin changed. Anything else is `needs_attention`
  with the problems named.
- `failed_no_change` is not a shrug: it needs an unchanged token, an unchanged inventory
  digest, an unchanged consistency baseline, **and** a `RECORD`-hash pass that finds no
  file the pre-install state did not already have broken. Damage sends the plan to
  `needs_attention` and keeps the mismatch list in the result.
- The terminal status write and the sibling staling share one transaction, so there is no
  gap in which a stale preflight could claim and downgrade.
- CLI activation: `check`, `preview` and `apply` route `uvtool`/`pipx` targets to
  `venvflow`, with a one-argv local runner adapter, so the venv kinds are reachable through
  the same commands as every other kind.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 341 tests, OK (12 new apply tests).
- Contract items covered by tests: the (0)–(5) refusals (no `--yes`, changed token, revived
  generation, changed fingerprint, changed inventory, missing constraints file), the
  classifier (a failure that changed nothing returns the plan to `proposed`; a failure that
  rewrote a file is `needs_attention` with `record_mismatches`), condition (4) (a new
  consistency entry), condition (5) (a swapped origin), and sibling staling on the terminal
  write.
- **End-to-end, live, through the CLI**, against a throwaway uv tool venv (`ruff==0.8.0`
