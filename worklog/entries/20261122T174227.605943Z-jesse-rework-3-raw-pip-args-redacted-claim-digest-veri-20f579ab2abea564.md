# rework 3: raw pip_args, redacted claim digest, verified copy runs, remove honours the lock

## Summary

The third audit found four defects that the previous round's tests could not see, because
they asserted on rebuilt argv rather than on the apply path itself.

## Changes

- `userlane._pip_args_index_options` no longer redacts: pipx `pip_args` now yield raw values
  like every other source, and `index_options_redacted` carries the storable form. A
  credentialed private index on the pipx path can authenticate again.
- The claim transaction compares `_index_options_redacted(t)` with the plan's digest, which
  is what the plan recorded. Comparing raw against a redacted digest refused **every**
  credentialed apply immediately after a successful preview.
- Step (5)'s verified temp copy is what actually runs: the argv is built against the
  `apply-*.tmp` path, and the equality gate folds that path back to the approved one before
  comparing, so the bytes uv reads are the bytes that were verified and a change to the
  preview file between the digest check and the read cannot slip through.
- `targets remove` refuses while any plan for the target or its venv is `running` or
  `needs_attention`, instead of retiring the row and orphaning an in-flight upgrade.

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 381 tests, OK.
- New tests in `tests/test_audit_fixes.py`:
  - `CredentialedIndexApplyTests.test_preview_then_apply_with_a_credentialed_index` runs
    preview **and** apply against a receipt carrying a credential, asserting `applied`, a
    raw URL in the install argv, and a `-c` path ending in `.tmp` (the verified copy).
  - `CredentialedIndexApplyTests.test_pipx_pip_args_keep_their_credential_for_use` covers
    the pipx source.
  - `RemoveRefusalTests.test_remove_refuses_while_an_update_is_running` covers the lock.
- `tests/test_register.py` updated: `index_options` is raw, `index_options_redacted` is what
  may be stored.
