# macos: coverage accounting matched to Homebrew's scanner

## Summary

This entry supersedes parts of the earlier macOS entry: eleven review
iterations against two reviewers changed how netwatch reads Homebrew's scan,
and the earlier description no longer matches the code.

## Changes

- Retention works by (formula, installed version) pairs through
  `coverage["retained_versions"]`: a finding is kept only while the version it
  was reported for is installed and the scan did not assess it. Uninstalling a
  formula, or upgrading it while Homebrew keeps skipping it, retires the
  finding.
- Coverage is counted against `brew info --installed` (236 formulae here),
  not `brew list --versions` (269 names): Homebrew never considers the
  difference, so counting it as covered was false.
- `checked` is `queryable.size` in Homebrew's scanner, so it includes
  `outdated_without_sbom` formulae; they stay inside the count and outside
  coverage. A scan whose count cannot account for the claimed set claims
  nothing and publishes nothing.
- `brew vulns` reports `full_name`, tap-qualified for third-party taps;
  `brew info --installed` provides the full_name to name map.
- Homebrew scans one keg per formula (`any_installed_prefix`). A matched row
  covers only the kegs sharing its base version; a clean multi-keg formula
  covers nothing, because the scanned keg cannot be identified.
- The scanner's version is used as reported; revision suffixes are stripped
  only when indexing installed kegs.
- `workflow.check` re-collects inventory after a scan that could clear prior
  findings; a mismatch retains everything and marks the check incomplete.
- Approved upgrades run without `HOMEBREW_NO_INSTALL_CLEANUP`, so the
  superseded keg is removed and a later check can confirm the new version
  clean; read-only commands keep the suppression.
- Update names and version fields are validated before storage; text report
  distinguishes same-named formula and cask rows and marks held and
  greedy-only entries.
