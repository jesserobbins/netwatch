# lifecycle state machine, lazy expiry and venv-scoped claims

## Summary

The upgrade kinds need one place that decides what a check observation means for a target's
state, and one predicate that says when two recorded paths are the same installation. Both
are shared machinery, so they land before any sensor exists and are tested on synthetic
events.

## Changes

- `netwatch/lifecycle.py`: `pair` (the one pairing rule: same generation, same `state_seq`,
  same field values, same identity input, neither event superseded or incomplete),
  `next_state` (one-shot facts — a clean identity failure, a malformed probe, a failed
  token write — before the two-in-a-row rules for absence, unreadable identity and token
  read errors; recovery for `identity_mismatch` and `unresolved_path`, refused while a
  co-claimant holds the venv), `recovery_candidate`, `publishable`, `state_seq_bump`,
  `expires`. Pure functions: no filesystem, no database, no clock.
- `workflow.same_venv` (normcased realpath equality or equal `(st_dev, st_ino)` of the
  resolved directories) and `workflow.busy_plan`: a plan blocks its own target **and** any
  target whose recorded path is the same venv, so a lock or claim travels with the
  installation rather than a name.
- `Store.expire`: lazy expiry of proposals past `expires_at`, recorded as a `plan_expired`
  event, run in the opening transaction of every store-writing command; `status`, `list`
  and `history` never expire anything.
- `Store.stale_siblings` plus `netwatch targets remove <name>`: retire a target, stale every
  proposed plan for it and for the same venv, keep its history and name, bump the
  generation so pre-removal plans are refused.
- Registration refuses a second target on a venv another target already tracks, using the
  same predicate; apply refuses the same conflict (step (2)'s second half arrives with
  Task 9 and calls this helper).

## Validation

- `.venv/bin/python -m unittest discover -s tests -q` — 273 tests, OK (45 new across
  `tests/test_lifecycle.py` and `tests/test_workflow_venv.py`).
- `tests/test_lifecycle.py` drives the state functions with dicts only: 30 cases covering
  pairing (generation, `state_seq`, superseded, incomplete, per-field values, identity
  input), one-shot facts, both two-in-a-row rules, recovery with and without a co-claimant,
  a foreign venv at an `unresolved_path` path, and the removed/superseded write bans.
- Existing brew and macports tests are untouched and still pin their behavior.
