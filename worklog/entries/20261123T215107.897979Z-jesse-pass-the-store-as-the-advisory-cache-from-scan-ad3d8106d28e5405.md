# pass the store as the advisory cache from scan

## Summary

The repo lane's `cache` parameter became a `Store`-shaped object (`cached_get`/`cached_put`), so `scan.run` and `scan.report` still passing `store.cached` would raise `AttributeError: 'function' object has no attribute 'cached_get'` on any repo whose lockfile parses packages — the state the previous entry left between this task and Task 4. No test covered that path, so the suite stayed green while the scan was broken.

## Changes

- `netwatch/scan.py`: both `tickets.collect` call sites (`run` and `report`) now pass `cache=store` instead of the callable `store.cached`. Nothing else in `scan.py` moved: no run-wide screen, no new parameters, no progress changes.
- `tests/test_scan_run.py`: new `RunTests.test_a_repo_with_locked_packages_scans_with_the_cache` — a scan over a root with one owned repo whose lockfile lists a package, against a real `Store`, asserting the locked package is queried once, the scan completes, and the ticket is recorded and written.

## Validation

TDD on the covering test: before the fix, `.venv/bin/python -m unittest tests.test_scan_run.RunTests.test_a_repo_with_locked_packages_scans_with_the_cache -v` failed with `AttributeError: 'function' object has no attribute 'cached_get'` (RED). After the two-line fix the same test passes, the module runs 18 tests OK (GREEN), and the whole suite `.venv/bin/python -m unittest discover -s tests -q` runs 444 tests, OK.
